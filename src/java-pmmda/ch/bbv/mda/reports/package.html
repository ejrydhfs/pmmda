Introduction

The pmMDA application provides a set of standard reports. They can be used to document a model, its stereotypes and all tagged values.

Reports

The reports provide criteria to select the subset of classes which should be included in the reports.

  • The list of packages which should be generated.
  • The list of stereotypes which are relevant. A class is part of the report only if it implements one of the listed stereotypes.
  • The list of cartridges which tagged values should be documented. The tagged values are identified through their prefix.

Each package contains the set of relevant classes with their properties and associated tagged values.

Design

The report engine is based on the open source free report. The data must be provided as a table model. The model must be transfered into a huge table where each tree node is a row and each property or tag is a column. The following conventions are defined to simplify the creation of custom reports.

  • The column name of based on positional notation. The name of the class is the first element. The legal values are model, package, class, datatype, property, and indexed property. The second element is either the name of the property or the name of the tag.
  • If the column value is defined for the row element, its value is returned otherwise null is returned. It is the responsibility of the report template to handle null values.
