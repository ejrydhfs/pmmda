The package provides the persistency mechanisms for MDA models.

Introduction

The package defines the persistency mechanisms for the business model of the pmMDA. These mechanisms implement data exchange between our application and third party tools. Multiple formats are supported to insure that the tool can exchange data with major open source modeling tools. The following exchange formats are supported.

    Java Serialize Format
    The Java serialization framework is fully supported. The format can be used to exchange efficiently data between pmMDA.
    XML Serialize Format
    The tree of objects are transformed in a XML format. The current XML long term persistency framework of Java cannot handle indexed properties based on lists or hash maps. Therefore we use the Jakarta Commons Betwist project to generate and read XML representations. The XML format supports long term persistency and migration to newer versions of the pmMDA MDA model.
    XMI 1.1 and MOF-UML 1.3
    The standard format XMI 1.1 and MOF-UML 1.3 is supported. UML modeling tools like MagicDraw, ArgoUML or Poseidon support it. Through the use of plugin model for Rational Rose can also be exchanged. This function is realized with the help of the NSUML library version 0.4.20. This format supports long term persistency and migration to newer versions of the pmMDA MDA model.
    XMI 2.0 and MOF-UML 2.0
    The standard format XMI 2.0 and MOF-UML 2.0 will be supported in the future. The function is realized with the help of the MDR library. This format is used in the NetBeans environment. This format supports long term persistency and migration to newer versions of the pmMDA MDA model.
    XMI 2.0 and Ecore 2.0
    This format is the exchange format used in the Eclipse environment. This format supports long term persistency and migration to newer versions of the pmMDA MDA model.

The UML 1.4 format is available to migrate old projects to newer UML versions. It should not be used for productive development.

Architecture

The persistency framework is based on a persistency handler defining the main functions to read, write and update description information. The persistency policy defines the detailed methods used to implement the retrieval functions.

XML Serialization

Releases 0.3.x and higher use the open source XStream library and serialize patterns. The following design decisions were taken.

  • Read object is as documented in "Effective Java" a factory method implementing a constructor of the class. Initialization of transient fields, computation of derived attributes and validation of class invariants must be performed in this method.
  • The Java library provide a method read resolve to insure that singleton patterns hold when serializing objects. This method must be provided for all classes implementing a singleton.
  • The JavaDoc environment provides tags for serialized properties. They must be used in the application to provide complete documentation.

General operations are provided as static operators to the project.
