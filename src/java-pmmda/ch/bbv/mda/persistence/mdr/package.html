The package provides converters between the MDR model and the MDA model.

Introduction

The package provides converters between the MDR model and the MDA model. They solve the semantic gap between the UML model and the Java bean representation of a class. The first major difference is that the bean concept is data oriented and UML is rather method oriented. Second UML has an artificial distinction between attributes and aggregations. Beans handle both as indexed properties.

Rules

Synchronization rules should be defined to align the pmMDA model with the underlying XMI model. The following rules are identified.

  • Newly added tag values must be added to the corresponding element of the model. This operation must at lest be performed when saving the model.
  • Removed tag values must be removed from the corresponding element of the model. This operation must at lest be performed when saving the model.
  • Modified tag values must also be changed in the corresponding element of the model. This operation must at lest be performed when saving the model.
  • Added attributes - either simple or indexed property with the flag attribute set - should be added to the corresponding element of the model. The operation is realized through the provided factory.
  • Removed attributes - either simple or indexed property with the flag attribute set - should be removed from the corresponding element of the model. The operation is realized through the provided factory.

The rules for the mutation of relations, classes and pacakges should be defined.

Mapping Rules

Mapping rules are necessary to transform attributes and relationships into simple and indexed properties. The transformation process uses the following rules.

  • An attribute with an undefined multiplicity or a multiplicity with a upper bound of one is mapped to a simple property.
  • An attribute with a multiplicity with a upper bound greater than one is mapped to an indexed property. The type of the property is only specified as the qualified name of the class or data type. The class object is retrieved at runtime.
  • An aggregation with an undefined multiplicity or a multiplicity with a upper bound of is mapped to an indexed property. The type of the property items is only specified as the qualified name of the class or data type. The class object is retrieved at runtime.
  • An aggregation with a multiplicity with a upper bound greater than one is mapped to an indexed property.
  • Undefined relations are not mapped.
  • Data types are read-only entities in the MDA model.

A well-designed UML model, which can be used as the basis for code generation should only contain directed composite aggregations.

General operations are provided as static operators to the project. @since Java 2 Platform, Standard Edition, version 1.5
