The packages defines a user interface to manipulate MDA models.

Introduction

The package defines a user interface to manipulate MDA models and fills all information needed to generate the source code artifacts tailored to the selected software platform. The user interface provides an efficient client to fill all needed stereotypes and tagged values. These activities could also be done with a UML CASE tool but quite less efficiently.

Views

The MDA interface provides views for each kind of artifacts, which should be generated. The views are.

  • The business object view allows the definition of business object classes. All properties and relationships can be defined.
  • The lightweight view allows the definition of the lightweight representation of business object classes.
  • The persistency view allows the definition of the persistency aspects of business object classes
  • The data transfer object view allows the definition of the data transfer object classes.
  • The user interface view allows the definition of the visual attributes of the business objects. Two kinds of user interfaces are supported. Complex clients using Swing and web based clients using Struts.
  • The properties view allows the edition of the properties of any MDA element and all its tagged values. The default display order of the tagged values is defined in the corresponding model element.

Features

Validation

Validation of a named element is performed after the user inputed new data in a properties view but before it is saved. If inconsistencies are found they are displayed in a todo list.

Persistency

The models are stored as XML files in the file system. Multiple formats are supported to enhance integration with other tools. The supported formats are defined in the documentation of the MDA busines object package. Interested readers can found detailed information there.

Command Line

The pmMDA Client supports a command line interface to streamline the start of the application with the expected configuration and data. The command line can also be used to execute the pmMDA application in batch mode. The following options are supported.

-v --verbose
An optional boolean argument. if set the logging level is verbose.
-q --quiet
An optional boolean argument. If set the logging level is quiet.
-h --help
-m --model "path-model"
Loads the given model at startup. The value defines the qualified file name containing the model to load. The command is optional.

Architecture

The architectural design of the pmMDA user interface has two major goals. First the amount of written code should be minimized. Second it provides a test bed for the new release of the explorer user interface framework.

Document Model

The application should provide a document model supporting the users.

  • If the user tries to leave the application and a modified model is available, he should be asked if he wants to save the model.
  • If the user generates artifiacts and a validation error exists, he should be informed that the artifacts could contain errors.

History

The prototype of the pmMDA was developed with the EMF framework of Eclipse. This framework uses passive code generators. This way of developing applications is against our beliefs how to develop applications. We decided to use the explorer framework to develop a new version of the user interface and implement strong validations of the data. The goal is to provide an efficient mechanism to define a PIM model of an application. Complex architectural modeling should be performed with a professional UML tool. Emphasis is put on validation and reporting and less on fancy features.
