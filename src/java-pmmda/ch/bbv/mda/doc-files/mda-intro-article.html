Abstract

The pmMDA project was started when developing complex applications with a clear application domain. The classes of the business domain were modeled in UML during the requirements and analysis phase. Now the development need to write their source code. The business model has orthogonal capabilities when mapped to software.

  • The classes must implement the properties of the specified business objects.
  • A subset of the business objects should be persisted. Usually the instances are stored into a relational database. The mechanism must provide ACID capabilities for create, retrieve, store and delete operations.
  • The business objects must often be sent between the server and clients. The transmission implements the data value object pattern to provide acceptable responsiveness on client side. Often a lightweight representation of the objects is used for navigation purposes.
  • The business object instances must be validated before being saved in the database. Often the validation rules are one key element why the application is developed.

The implementation of the above views is tedious and repetitive. Modern UML modeling tools are tailored to generate the business object layers. Additional views must first be inputed in the tool before you can generate it. Often the tool does not handle the semantic dependencies between the various views.

pmMDA is an attempt to pragmatically solve the above problems. The resulting tool is an adaptive code generator for all the above views. The model is based on the MDA initiative from the OMG group. The next chapters describe the current state of the industry practices, provide details about MDA, present the pmMDA results and give a glimpse of future development.
