Introduction

The process development is an agile version of the unified software development process USDP. The process is architecture centric, iterative and uses object-oriented methods. The iterative process uses continuous integration cycles as published in seminal articles. For a discussion about the advantages of continuous integration and test cycles consult continuous integration. The integration cycle is automated with Ant tasks.

Processes and Tools

Requirement traceability is done with cross reference tables. The tables are currently filled manually.

The planning and desing rules try to eliminate unecessary tasks. Here a list of seven common pitfalls where resources are wasted.

  • Partially done work also called the inventory of a development process.
  • Extra processes are especially easy to find in documentation-centric development.
  • Extra features instead of developing only what customers want right now.
  • Task switching instead of doing one thing at a time.
  • Waiting for instructions or information.
  • Handoffs where tons of tacit knowledge gets lost.
  • Defects that are not quickly caught by a test.

The agile process is backed with the following tools.

    Analysis and design
    The UML modeling tool ArgoUML is used.
    Development environment
    The Eclipse integrated development environment is used. The programming laguage is Java and is based on JDK 1.4. The project heavily uses open source components from the Apache Jakarta project. Continuous integration is realized with ant scripts and JUnit unit testing framework.
    Version management
    The version management CVS is used. The continuous release paradigm is used. Tagged versions contain all the artifacts needed to generate a fully functional applications with its deployment scripts and documentation.
    Documentation
    The documentation uses the features of the JavaDoc tool. Extension doclets transform the documentation into DocBook, poscript and PDF formats. The documentation is published online using Apache and Tomcat. Test documents are written with OpenOffice.
    Issues tracking
    The issue tracking system Scarab is used.
    Quality assurance
    Source code is checked with JDepend , PMD and javaNCSS. Detailed documentation is checked with DocCheck Sun doclet. Architectural design is verified through walk-throughs. These metrics are generated each time a new integration cycle is performed.
    Testing
    Unit testing is performed with the JUnit test framework.
