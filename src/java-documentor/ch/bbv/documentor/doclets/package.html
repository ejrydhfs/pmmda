The UML model synchronization application uses the JavaDoc information of a Java source code tree to synchronize an UML model with the source code.

Purpose

The UML model synchronization application uses the JavaDoc information of a Java source code tree to synchronize an UML model with the source code. The goal is to synchronize and not to enhance the model. Often UML models have less details than the source code to increase their legibility.

Rules

The following synchronization rules are defined.

  • No new classes are added to the UML model. Therefore all implementation specific classes never polute the domain model.
  • The methods and static declarations of any interface in the model are updated to reflect the Java interface declaration. The list of interfaces defined in the source tree and not in the model are logged.
  • The properties and methods of all classes without the stereotype "business object" or "reference code" are updated to reflect the Java class declaration.
  • The classes with the stereotype "business object" or "reference code" are never updated. The UML model is the master and the Java source code is assumed to be automatically generated using a MDA approach. The user must always perform modifications in the UML model or through the pmMDA application.

Architecture

The doclet architecture uses the pmMDA metamodel as the model representation to manipulate.

Documentor Origins

The documentor project was started as a huge perl script used to document C/C++ projects. The target was HTML, LaTeX and PDF. The goal was to generate legible API documentation. Advanced concepts such preconditions, postconditions and invariants were already supported. The first version was released as open source in 1994. The project evolved to support round-trip engineering and synchronize source code artifacts with Rational Rose models. Extensions were added to support real-time modeling such as synchronization and message passing.

The project was fully rewritten in the second part of the nineties. The implementation language is now Java. The IBM COM bridge is used to interface with external Booch and UML tools. Step by step the internal documentor model was moved to the JavaDoc model with some extensions to support multiple inheritance.

The support of C++ was canceled in 2002. The responsible for the maintenance of these functions moved to another company and could no more provide resources for the document project. The open source tool Doxygen provides wonderful documentation capabilites for C/C++ projects.
