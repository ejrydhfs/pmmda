Introduction

Business object models are validated against a set of business rules. The rules are defined as validation rules. The business object types being Java beans, the rules are connected to the model through the bean descriptor meta-model. All feature descriptors support set and get of named values. All rules must implement the validation rule interface. A set of standard rules are provides as examples. They are discribed below.

The package provides a set of predefined rules useful for typical checks such null values, uniqueness, regular expressions based format verification.

Design

The framework supports the definition and registration of validation rules to check properties and beans. Users can defined their own rules and register them in a validator instance. A powerful extension would be to have the ability of composing rules. Here a set of composition rules and their meaning.

Conditional Execution
The rule is only checked if the condition is true. The condition is specified as functor.

Validation Types

Range Check
The property must be inside the defined range of values. All primitive types and their wrappers, big decimals, big fractionals and dates are supported.
Pattern Check
The string property value respects the defined regular expression. Minumum and maximum length of a text are also handled in this check.
Is null
The property value is null.
Is not null
The property value is not null.
Is unique in a collection
All the values of an indexed property are unique. A parameter controls if null values are relevant or not.
Collection rule
A rule is applied on all the items of an indexed property. The rule can be freely configured.

Architecture

The validation framework uses the bean standard packages to store the validation rules. A rule is either stored in the bean information instance of a class or in the property descriptor of a property. The list of valid rules is added as a named attribute to the bean information object. The list order defines the order of evaluation.

Validators are found through the locator services. Multiple validators can be defined. Each must have a different name. The names are used to identify the set of rules it should compute.

Conventions

The values are identified through names. Conventions must be defined to find out where validation rules are stored in the descriptors.

  • The validations rules of a property are defined as a set of rules. They are stored in the property descriptor. The set is stored under the name "validation".
  • The validations rules of a bean are defined as a set of rules. They are stored in the bean descriptor. The set is stored under the name "validation".
