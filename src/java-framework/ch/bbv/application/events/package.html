Event mechanisms are provided to communicate in client/server environments.

Purpose

Complex client server applications often communicate with other servers or are part of a company wide workflow. For example the accounting system can modify administrative information of a contract in the contract and document management system.

Some application changes have impact on the clients currently working. The concerned client applications should be informed when such changes are comitted. So the user will not try to edit obsolete data or perform operations no more legal in the new context. The server should push selected information to all interested clients. The amount of data and the number of occurences should stay at a reasonable level. Otherwise the system will not scale when the number of concurrent clients increases.

Architecture

Events are propagated through channels. A channel has two ends. One end is used to send events, the other end is used to receive events. At most one provider can send events through a channel. Multiple listeners can receive events from a channel.

Channels can use different middleware transmission medium to transmit events to interested listeners. The framework provides hot plugins to add new channel types.

Java Channel

The Java channel propagates events inside a Java virtual machine. The channel source and listeners are all registered in an event manager. The channel dispatches the event messages as synchronous calls. This channel type is optimal for internal communications or during the development phase.

EmailChannel

The email channel propagates events to listeners connected to the Internet email system. Each listener registered to an email channel should define an email property otherwise the events cannot be dispatched to them. The email message header identifies the channel and its type, the body contains the XML representation of the event.
