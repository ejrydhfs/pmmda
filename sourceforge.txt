0. Configuration
   -------------
   The ant tasks in the "build-sourceforge.xml" scripts require that the jar 
   files stored in "./scripts/lib" are accessible to ant. The simpliest 
   solution is to copy all jar files in the "lib" directory of your ant 
   installation. The same operation should be done for the xslt files stored
   in "./scripts/resources/xslt"; they should be copied in the "etc" directory
   of your ant installation.	

1. Prepare distribution
   --------------------
- Verify that the version of all used components is the one of the component
  stored in the lib directory. 
- Run "sourceforge" target to generate distribution. Verify that the 
  completness of the web site with its references to metrics and JavaDoc.
- Run "build-all-tests" target to generate the test examples.
- Run each test application with the provided shell scripts.
- Execute the sanity test cases - 2-tiers, CORBA, and J2EE -.

1.1 Sanity Tests
    ------------
- Run pmMDA with example test and MySQL, JBoss, no DDL Utils
- Run pmMDA with example test and Derby, JBoss, no DDL Utils
- Run pmMDA with example test and MySQL, JBoss, DDL Utils
- Run pmMDA with example test and Derby, JBoss, DDL Utils


1.2 Update web site
    ---------------
The list of external libraries used in the project must be updated in the site.
Do not forget to update the version of the libraries.

The latest news for each subproject should be updated.

Upon completion the web site should be regenerated with forrest.

2. Binary and source distribution
   ------------------------------
The binary and source distribution of all subprojects are published with a 
version number in sourceforge.

The following steps must be done before the release.
- Update the build properties with the new release versions. Release candidates
  are marked with a RC postfix follow with a revision number.
- Update the release notes of all components and projects.
- Generate the distributions (using the ant jobs defined in 
  build-sourceforge.xml).
- Generate the zip file containing all librairies necessary for development.
- Commit to sourceforge CVS and tag the release. This operation is done in 
  Eclipse.
- Upload the distribution files and the library file using anonymous FTP
  (See sourceforge for details).
- Register them in the sourceforge project in the file list. If necessary remove
  the oldest ones to keep the number of versions reasonable.
- Write the news entry on the site.
- Send an email informing all developers of the update. The list is defined in
  sourceforge "pmmda-developers@lists.sourceforge.net".

The following steps must be done after the release
- Verify that the uploaded distributions can be downloaded and installed.
- Donwload the pmMDA binary distribution and execute the two minutes tutorial
  as described on the web site.
- Update the build properties with the next version number and the postfix 
  "-dev". Normally only the patch number should be incremented.
- Update the version number in the pmmda application.

2.1 pmmda distribution
    ------------------
- Update version number in project description in the MdaExplorer file.

3. Web site distribution
   ---------------------
The sourceforge account provides up to 100 MB disk space for the web site.
The following steps are necessary to create and upload the site.
- Generate the site (using the ant jobs defined in build-sourceforge.xml)
    create javadoc - ant javadoc -
    create metrics - ant metrics -
    create forrest - ant forrest -
    create sourceforge - ant sourceforge implies forrest -

- Upload the site
   pscp -r -C d:\data\projects\pmmda\build\site\* 
        marcelbaumann@shell.sourceforge.net:/home/groups/p/pm/pmmda/htdocs
   upon request give password of developer account.
   The web site contains the complete JavaDoc documentation of the project
   and sourceforge request SSH2 accesses therefore the upload time using 
   an ADSL link is still about thirty minutes.

5. Mailing list management
   -----------------------
   
You can configure your mailing list at the following web page:

    https://lists.sourceforge.net/lists/admin/pmmda-developers

The web page for users of your mailing list is: 

    https://lists.sourceforge.net/lists/listinfo/pmmda-developers

You can even customize these web pages from the list configuration page.  
However, you do need to know HTML to be able to do this.

There is also an email-based interface for users (not administrators) of your 
list; you can get info about using it by sending a message with just the word 
`help' as subject or in the body, to:

    pmmda-developers-request@lists.sourceforge.net

To unsubscribe a user: from the mailing list 'listinfo' web page, click on or 
enter the user's email address as if you were that user. Where that user would 
put in their password to unsubscribe, put in your admin password.  You can also 
use your password to change member's options, including digestification, 
delivery disabling, etc.

Please address all questions to mailman-owner@lists.sourceforge.net.
